Hooh — from understanding a document to acting on it

Hooh shipped as a reader — it could tell you what a document said. The next release turned it into a tool you act with: fill and sign forms, mark them up, reorganize and edit pages, convert and translate — a full document toolbox on iOS. The hard part wasn't any single tool. It was adding real power to an app used by people without a legal background, without ever making it feel like a power tool — and without putting their original at risk.

Problem

Hooh could read a document, but not act on it. Everything after reading — filling a form, signing it, marking it up, straightening a crooked scan, converting it to send — meant exporting to another app. For a non-technical audience, that handoff is exactly where the value leaked, and where mistakes happened: a lost original, an overwritten file

Task

Turn the reader into a complete document workspace on iOS — fill, sign, annotate, edit, convert — while keeping the simplicity that made Hooh approachable, and guaranteeing the user never loses control of, or destroys, their original

Users

The same audience as the first Hooh release — expats, digital nomads, and people without a legal background. They handle a steady trickle of documents — forms, contracts, scans, paperwork — and want them dealt with, not a toolbox to learn

Scope

A document-action toolset on one rule — automate where it saves time, keep every step reversible, never touch the original. Smart Fill with a manual fallback, a reusable signature, a markup and annotation system, page and edit tools, format conversion, and an explicit version model

Design process

Sessions with the first-release cohort surfaced the pattern: people understood their documents but stalled the moment they had to do something with them — and the tools that could help lived in five different apps. The opportunity was to bring acting on a document into the same place as understanding it.

One constraint shaped every tool below: control. Power is only safe for this audience if it's reversible and never destructive. Across the whole toolset the rules are the same — automate visibly, let the user override or undo, and keep the original untouched. Every feature is a variation on that one promise.

1. Smart Fill — automation with a veto

Hooh recognizes form fields and fills them from the user's stored documents — and nothing is submitted silently. When Smart Fill has a match, the documents it drew from stay pinned at the top, so the user sees its sources; any value can be overridden in place; and a single toggle hands the whole form back to manual entry. It defaults to on because the time saved is the point, but the user is never more than one tap from doing it by hand. When a field has no match, the form highlights it and keeps moving — an unfinished form is a first-class state, not an error.

2. Signature — captured once, reused everywhere

One signature, made once. Draw it on the canvas or capture an existing one with the camera — either way it becomes a reusable asset, saved to a library and ready to drop into the next document. The user makes the signature itself only once.

3. Annotate & edit — power without a learning curve

Marking up a document is where an editor usually turns into a power tool. Hooh keeps one tool picker at the bottom and one color system across every tool — highlight, text, shapes, freehand markup — so the controls never multiply. Tools place where the user taps, parameters open in a single sheet, and everything sits as a non-destructive layer over the original: undo any mark, or peel the whole markup off, and the source is exactly as it was. 4. Saving & versions — the original is never at risk

Saving never overwrites by accident. The original file stays untouched — the user can save a new copy or branch off a brand-new document, and every version lives inside the document itself: switchable from the nav bar and renamable in place. Iterating on the same form keeps every state without cluttering the document list. This is the backbone of the whole toolset's promise: nothing the user does is destructive.

Outcome

The toolset was designed end-to-end and handed off to engineering. Read separately, the features are a form-filler, a signer, a markup tool, a converter; read together, they're one argument — Hooh can do far more to a document than read it, and still never takes control away from the person holding it.

This scope didn't reach a public release as part of this engagement, but the system, components, and flows are documented and ready to ship when the product picks the work back up.
