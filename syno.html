Syno: an art platform from scratch

Syno is Cyprus’s art platform for artists, organizations and visitors: events, portfolios and open call applications. The brief described these sections separately. I connected them into a single model, designed the UX and UI of every section, built the code prototype and supported development.

Task

Design an art platform from scratch: an artist registry, an open call and an event map, connected by shared data, roles and rules.

What I Did

Flows and product rules, responsive layouts, a design system, specs and design reviews.

How I Worked

I designed much of it in the code prototype: unlike static mockups, the whole platform works there, making it easy to test how sections connect. I built the mockups for development in Figma and checked the finished build against them in design reviews.

The timeline was tight, so I analyzed the client’s data from conversations with artists, and we tested the prototypes within the team.

Scope

Home, the Art Map, the registry and artist profile, Stories, the open call and application, the My Syno dashboard, organization and event pages. Desktop and phone.

Benchmarking

CaFÉ: applying without re-uploading

For every open call an artist gathers the same things: works and a Statement. On CaFÉ you upload works once and only pick them when applying. Applications in Syno rest on the portfolio too: the works and Statement come from it.

Open calls: a draft instead of Save

Across 10 open call pages, no organizer offers saving. Only aggregators like ArtConnect do. Syno runs its own open call, so the draft application is what brings an artist back.

Artsy and Ocula: follower counts

Artsy shows follower counts to everyone. Ocula and ArtRabbit show none. Cyprus’s art scene is small, so 3 next to 40 would read as a ranking of artists. In Syno only the people who manage a page see the count.

Public sections

1. From an event to the artist

I linked the map, events and portfolios into one route: pick an exhibition, check the time and place, go to the participant’s works. An event opens over the map, so filters are kept. Filters, search and the open event are stored in the URL, so a link opens the same results.

Save survives sign-in

If someone taps Save without signing in, they return to the same item after sign-in, and it is already saved. Deleted items do not disappear from favourites without explanation: the card stays, marked “No longer on SYNO”.

2. Events: at once or after review

Anyone with an account can create an event: an artist, an organization, a visitor. Only moderation depends on the author, so the author is chosen before the form is filled in. The venue is set separately: a personal event at NiMAC does not make the author part of the NiMAC team.

Weekdays were added after the event page review: a date range without them showed a Saturday studio as open on a Tuesday.

An event can be withdrawn in two ways: Cancel if it will not take place, Delete if it was created by mistake. A cancelled event leaves the map but stays available at its link and to those who saved it, as on Meetup.

3. Organization dashboard and team access

For the organization dashboard, the client named ArtRabbit as the reference. I studied its flows on a live account, gathered the requirements and brought the key questions to discussion: who submits events, who gets reviewed, how to confirm the right to a page. These decisions determined the moderation load.

Syno confirms the right to a venue page through the website or the email domain, with no documents.

4. A portfolio the artist controls

The artist publishes the portfolio — jury selection applies only to open call applications. Publishing needs the mediums, a Statement and at least one work: the checklist shows what is missing before Publish is pressed.

One uploader works across the portfolio, the application, the event and the venue page: progress, errors and retries show directly on the file tile.

In an early mockup a single crop cut landscape works, so I removed it.

5. One application for a new and an established artist

Both go through the same steps: details, works, questions and review. Anything missing can be added along the way.

On submission the application fixes copies of the Statement and the works, so later portfolio edits do not affect the jury materials. I dropped a second, synced Statement: after the first edit it would be unclear which version is current.

What I revised along the way

Registry of the selected → open registry

In the brief a profile entered the registry only after the jury’s selection. Together with the client we opened the registry to every artist, and the readiness checklist became the condition for publishing.

Separate roles → one account

In the brief an artist and a venue representative were separate roles. Now one account combines a personal profile and any number of organizations.

Request → invitation

At first, access to a venue page could be requested. We dropped requests: people join the team by invitation, and the owner does not have to sort through strangers’ requests.

Outcome

The public version is live on syno.art: home, Art Map and the open call page. The development team built the final version. Open Call 2026 received more than 50 applications.

Next stage: dashboards. After launch we will test the model on data: how many applications are built from an existing portfolio, how many profiles reach publication, how many personal events go back for changes.
